# AI 智能分析演示脚本

> 版本：Phase 4（AI Agent 已接入）
> 适用场景：客户 Demo / 内部验收
> 预计时长：每个示例 10–15 分钟

---

## 演示背景

向客户说明：平台的 AI 分析能力建立在 **Ontology 语义层**之上，不需要任何模型训练或数据标注。业务人员用自然语言提问，系统自动完成跨实体关联查询、多维聚合计算和报告生成。

```
传统 BI 工具：数据工程师写 SQL → 分析师配置图表 → 等待数天
本平台：业务人员直接提问 → 秒级返回分析报告
```

## 示例一：客单价多维分析

> 展示 AI Agent 跨实体关联查询 + 多维聚合 + 自动报告生成
> 预计时长：10 分钟

---

### 第一步：进入 AI 分析页面

**路径**：顶部导航 → **分析** → 点击右上角 **「新建分析」**

页面展示一个自然语言输入框，下方显示最近使用的分析记录。

---

### 第二步：输入分析请求

在输入框中输入：

```
将客单价按品类、地域、性别各自分类，给出一份分析报告
```

点击 **「分析」** 按钮（或按 Enter）。

---

### 第三步：观察 Agent 推理过程（透明可见）

系统右侧展开「**推理步骤**」面板，实时显示 Agent 的工作过程：

```
✦ 意图理解
  检测到分析目标：客单价（= 订单总金额 / 客户数）
  检测到分析维度：品类 / 地域 / 性别（共 3 个维度）

✦ Schema 检索
  匹配 EntityType：
    Order（amount, created_at）
    Customer（gender, region）
    Product（category, name）
  匹配 LinkType：
    Order -[PLACED_BY]-> Customer
    Order -[CONTAINS]-> Product

✦ 查询分解
  维度 1：AVG(Order.amount) GROUP BY Product.category
    → 图遍历：Order → Product，DataFusion 聚合
  维度 2：AVG(Order.amount) GROUP BY Customer.region
    → 图遍历：Order → Customer，DataFusion 聚合
  维度 3：AVG(Order.amount) GROUP BY Customer.gender
    → 图遍历：Order → Customer，DataFusion 聚合

✦ 执行中...
  NebulaGraph 图遍历：3 条路径，共 12,483 条订单关联记录
  DataFusion 聚合：3 个维度，耗时 280ms
  报告生成中...
```

> **向客户说明**：推理过程完全透明，每一步都可以查看，与 Palantir AIP 的黑盒不同。业务人员可以验证 AI 的推理路径是否符合业务逻辑。

---

### 第四步：查看分析结果

分析完成后，页面展示三个区块：

#### 区块 1：品类维度

| 品类 | 客单价 | 订单数 | 占比 |
|------|-------|-------|------|
| 电子产品 | ¥3,248 | 1,832 | 14.7% |
| 家居用品 | ¥1,560 | 2,941 | 23.6% |
| 服装配饰 | ¥ 580 | 4,217 | 33.8% |
| 食品生鲜 | ¥ 320 | 3,493 | 28.0% |

**AI 洞察**：电子产品客单价最高，是食品生鲜的 10 倍。但服装配饰和食品生鲜贡献了超过 60% 的订单量，是高频低价品类。

#### 区块 2：地域维度

| 地域 | 客单价 | 订单数 | 环比上月 |
|------|-------|-------|---------|
| 华东 | ¥1,850 | 4,218 | ▲ 8.2% |
| 华南 | ¥1,620 | 3,107 | ▲ 3.1% |
| 华北 | ¥1,430 | 2,891 | ▼ 1.4% |
| 西部 | ¥ 920 | 2,267 | ▲ 12.6% |

**AI 洞察**：华东客单价最高，是西部的 2 倍。但西部环比增速最快（+12.6%），存在高速增长潜力，建议加大西部市场投入。

#### 区块 3：性别维度

| 性别 | 客单价 | 订单数 | 复购率 |
|------|-------|-------|-------|
| 男性 | ¥1,680 | 5,832 | 34% |
| 女性 | ¥1,240 | 6,651 | 51% |

**AI 洞察**：男性客单价高 35%，但女性下单频次和复购率显著更高。女性用户的 LTV（生命周期价值）可能更优，建议结合复购数据进一步分析。

#### 综合报告

```
📊 综合洞察（AI 生成）

本期共分析 12,483 笔订单，整体客单价 ¥1,348。

核心发现：
1. 品类结构失衡：高客单价的电子产品订单量占比仅 14.7%，
   提升该品类渗透率是拉升整体客单价的最高效路径。

2. 地域分化显著：华东客单价是西部的 2 倍，西部增速最快，
   建议在西部优先推广高客单价品类（电子产品/家居）。

3. 性别策略分化：男性适合高客单价大额促销，
   女性适合高频次会员体系，两类策略不应混用。

建议下一步分析：
→ 「西部 + 电子产品」的交叉细分客单价趋势
→ 女性用户复购周期与品类偏好分布
```

---

### 第五步：深钻查询（Agent 多轮对话）

基于上方洞察，在输入框继续追问：

```
西部地区的电子产品客单价近6个月的趋势是什么？
```

Agent 自动继承上下文，增量执行：

```
✦ 上下文继承
  复用上次查询：Customer.region = '西部' + Product.category = '电子产品'
  新增条件：created_at 近 6 个月，按月分组

✦ 执行
  DataFusion：WHERE region='西部' AND category='电子产品'
              GROUP BY MONTH(created_at)
              ORDER BY month ASC
```

返回折线图数据 + AI 趋势判断：

```
月份      客单价    环比
10月     ¥2,810   基准
11月     ¥2,950   ▲ 5.0%
12月     ¥3,420   ▲ 15.9%（双十二拉升）
 1月     ¥2,680   ▼ 21.6%（节后回落）
 2月     ¥2,730   ▲ 1.9%
 3月     ¥3,150   ▲ 15.4%（持续回升）

AI 判断：西部电子产品客单价呈上升趋势，受节假日影响明显。
         3 月回升强劲，建议 4 月加大西部电子品类备货。
```

> **向客户说明**：Agent 支持多轮对话，每次追问自动继承前序上下文，无需重新描述分析范围。

---

### 第六步：保存为命名 Object Set / 报告

点击右上角 **「保存分析」**：

- **保存为 Object Set**：「西部高价值订单」= `Order where region='西部' AND category='电子产品'`，后续可在 Browse 页直接引用，也可绑定告警（新订单进入时通知）
- **导出报告**：生成 PDF / Markdown，供管理层查阅
- **订阅更新**：每月 1 日自动重跑，将更新结果推送给指定负责人

## 示例二：供应商风险预警分析

> 展示 AI Agent 多跳图遍历 + 风险评分 Function + 自动触发 Action
> 预计时长：15 分钟

---

### 场景背景

向客户说明：这个示例展示"分析 → 发现风险 → 自动触发操作"的完整闭环，是 Ontology 平台区别于普通 BI 工具的核心能力。

---

### 第一步：输入风险分析请求

在 AI 分析输入框输入：

```
找出近3个月交货延迟超过2次的供应商，分析其关联合同的潜在风险
```

---

### 第二步：观察多跳图遍历过程

推理面板显示：

```
✦ 意图理解
  目标对象：Supplier（供应商）
  过滤条件：近3个月 delivery_delay_count > 2
  关联分析：→ Contract（合同）的潜在风险

✦ 查询分解
  Step 1（DataFusion）：
    SELECT supplier_id FROM suppliers
    WHERE delivery_delay_count > 2
    AND last_delivery_date > NOW() - 90 days
    → 候选供应商：23 家

  Step 2（NebulaGraph 多跳遍历）：
    GO FROM [23个供应商ID]
    OVER supplies_to             // 供应商 → 合同
    OVER involves                // 合同 → 订单
    WHERE Contract.status = 'active'
    → 关联活跃合同：47 份
    → 关联未完成订单：312 笔

  Step 3（Function 计算）：
    计算每份合同风险评分
    = 延迟次数 × 合同金额权重 + 未完成订单数
    → 高风险合同：8 份（评分 > 80）
```

---

### 第三步：查看风险分析结果

#### 风险供应商列表

| 供应商 | 延迟次数 | 关联合同金额 | 风险评分 | 状态 |
|-------|---------|------------|---------|------|
| 某某电子 | 5次 | ¥2,380万 | 94 | 🔴 高风险 |
| 某某物流 | 4次 | ¥1,200万 | 87 | 🔴 高风险 |
| 某某零件 | 3次 | ¥ 680万 | 72 | 🟡 中风险 |
| ... | ... | ... | ... | ... |

#### AI 综合报告

```
⚠️ 供应链风险预警报告

发现 23 家存在交货延迟的供应商，其中 8 家关联高风险活跃合同。

最高风险：某某电子（风险评分 94）
  - 近3个月延迟 5 次，涉及合同金额 ¥2,380 万
  - 关联 12 笔未完成订单，预计影响本季度交付
  - 建议：立即启动备选供应商评估

系统性风险：
  47 份关联合同总金额 ¥8,600 万，占本季度采购总额 34%
  如主要延迟供应商同时违约，将影响 312 笔客户订单

建议行动：
→ 对评分 > 80 的 8 家供应商发送「风险预警通知」
→ 对评分 > 90 的 2 家启动「暂停合作」流程
```

---

### 第四步：一键触发 Action（分析 → 操作闭环）

报告下方显示 **「建议操作」** 区块：

```
基于以上分析，可以立即执行：

[⚡ 对 8 家高风险供应商发送风险预警通知]   → 预览 8 家名单
[⚡ 对 2 家极高风险供应商启动暂停合作流程]  → 预览 2 家名单
[📋 将「高风险供应商」保存为 Object Set]    → 供后续持续监控
```

点击 **「对 8 家高风险供应商发送风险预警通知」**：

- 弹出预览确认框，列出 8 家供应商名单和通知内容预览
- 点击 **「确认执行全部」**
- 系统逐条执行 `send_risk_alert` Action，执行历史写入 `action_executions`
- 返回摘要：**成功 8 家，失败 0 家**

> **向客户说明**：
> - 分析结果直接触发 Action，**分析和操作在同一平台内闭环**，不需要切换到其他系统
> - Agent 执行批量 Action 前必须人工预览确认，不会自动乱操作
> - 所有操作写入审计记录，事后可完整追溯
> - 「高风险供应商」保存为 Object Set 后，可设置每日自动重跑，新进入的高风险供应商自动触发告警

## 常见问题 QA

**Q：AI 分析的数据准确性如何保证？**
A：每一步查询条件都展示在推理面板中，业务人员可以核验。DataFusion 执行的是精确 SQL 聚合，不是 AI 生成的估算数字。AI 只负责理解意图和生成报告，计算本身是确定性的。

**Q：支持多少个维度同时分析？**
A：理论上没有限制。实际瓶颈在于 NebulaGraph 图遍历的跳数和 DataFusion 的聚合维度数，当前配置支持 10 个以内维度的交叉分析。

**Q：历史数据可以分析吗？**
A：可以，只需在问题中加入时间范围即可，如"过去12个月"、"2024年Q3"，Agent 自动转换为时间过滤条件。

**Q：非技术人员能用吗？**
A：这正是设计目标。输入框支持自然语言，不需要了解 SQL 或数据结构。推理步骤面板对技术人员开放，对业务人员可收起。

**Q：分析报告可以定期自动生成吗？**
A：可以。保存分析后，设置「订阅更新」，选择频率（每日/每周/每月），系统自动重跑并将报告推送给指定人员。
