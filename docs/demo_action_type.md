# ActionType 功能演示脚本

> 版本：Phase 3（执行引擎已接入）
> 适用场景：客户 Demo / 内部验收
> 预计时长：每个示例 10–15 分钟

---

## 演示背景

向客户说明：平台的 ActionType 采用**模板/实例**两层设计，与 EntityType → OntologyObject 完全对称：

```
EntityType  (Schema 层·模板)  ──▶  OntologyObject  (Browse 层·实例)
ActionType  (Schema 层·模板)  ──▶  Action          (Object 上·执行实例)
```

业务人员在 **模型** 页定义 ActionType 模板（"哪些角色可以对哪些状态的对象做什么操作"）；用户在 **浏览** 页对具体对象触发 Action 实例。执行引擎（Rust ActionRegistry）已在后端接入，状态流转和执行记录实时写入数据库。

## 示例一：Order 订单履单全链路

> 系统中已有 10 条 Order 对象（or1–or10），状态分布在 Processing / Shipped / Delivered / Cancelled 四个值上。本示例基于真实数据，从数据导入状态机，配置三个 Action，演示完整履单流程。
> 预计时长：10 分钟

---

### 第一步：配置状态机

**路径**：顶部导航 → **模型** → 左侧列表点击 **Order**（带 AR 标记）→ 向下滚动找到「状态机」面板 → 点击展开

#### 1-1 从数据导入全部状态（一键完成）

1. 点击面板右上角 **「从数据导入」** 按钮
2. 系统分析 Order 对象数据，弹出对话框
3. 下拉框选择 **`status`** 字段，右侧显示检测到 **4 个枚举值**：`Processing`、`Shipped`、`Delivered`、`Cancelled`
4. 全部勾选，为每个值选择颜色（见下表），点击 **「导入 4 个状态」**

最终状态列表：

| 名称（英文）   | 显示名称 | 颜色       | 标记       |
|-------------|---------|-----------|-----------|
| `Processing` | 处理中   | `#f59e0b` | ☑ 初始状态 |
| `Shipped`    | 已发货   | `#8b5cf6` |           |
| `Delivered`  | 已送达   | `#10b981` | ☑ 终止状态 |
| `Cancelled`  | 已取消   | `#ef4444` | ☑ 终止状态 |

> 导入后点击各状态的 **✎ 编辑** 按钮，为 `Processing` 勾选「初始状态」，为 `Delivered` 和 `Cancelled` 勾选「终止状态」。

#### 1-2 配置转换规则

向下找到「转换规则」区域，点击 **「+ 添加转换」**，添加 3 条规则：

| 起始状态 | 目标状态 | 说明           |
|--------|--------|--------------|
| 处理中   | 已发货   | 仓库出库，交付快递  |
| 已发货   | 已送达   | 客户签收确认     |
| 处理中   | 已取消   | 订单取消        |

观察：状态图自动刷新，出现主链路 **处理中 → 已发货 → 已送达** 加分支 **处理中 → 已取消** 的四节点图。

---

### 第二步：声明 ActionType

**路径**：同一 Order 详情页 → 展开「Action 模板」面板 → 点击 **「+ 新建」**

#### Action 1：发货

| 字段          | 填写内容        |
|-------------|----------------|
| 名称（英文）   | `ship_order`   |
| 显示名称      | 发货             |
| 层级          | 对象级           |
| 触发方式      | 手动             |
| 允许的起始状态 | ☑ 勾选**处理中** |
| 执行后状态    | 下拉选**已发货** |

**参数配置**：

1. 点击 **「从字段选择」** → 勾选 `total_amount`（number）→ 点击「添加 1 个」
2. 点击 **「+ 手动添加」** 两次：
   - `tracking_no`，string，☑ 必填（快递单号）
   - `shipped_by`，string，☑ 必填（操作人）

| 参数名          | 类型    | 必填 |
|--------------|--------|------|
| `total_amount` | number | ☑  |
| `tracking_no`  | string | ☑  |
| `shipped_by`   | string | ☑  |

点击「创建」→ 点击 **「激活」**。

#### Action 2：确认收货

| 字段          | 填写内容            |
|-------------|-------------------|
| 名称（英文）   | `confirm_delivery` |
| 显示名称      | 确认收货             |
| 层级          | 对象级               |
| 触发方式      | 手动                 |
| 允许的起始状态 | ☑ 勾选**已发货**     |
| 执行后状态    | 下拉选**已送达**     |

**参数配置**（全部手动）：

| 参数名            | 类型    | 必填 | 说明       |
|----------------|--------|------|----------|
| `received_by`  | string | ☑    | 签收人     |
| `delivery_note`| string | ❌   | 备注（可空）|

点击「创建」→「激活」。

#### Action 3：取消订单

| 字段          | 填写内容        |
|-------------|----------------|
| 名称（英文）   | `cancel_order`  |
| 显示名称      | 取消订单         |
| 层级          | 对象级           |
| 触发方式      | 手动             |
| 允许的起始状态 | ☑ 勾选**处理中** |
| 执行后状态    | 下拉选**已取消** |

**参数配置**：

| 参数名           | 类型    | 必填 | 说明   |
|----------------|--------|------|------|
| `reason`       | string | ☑    | 取消原因|
| `cancelled_by` | string | ❌   | 操作人 |

点击「创建」→「激活」。

确认「Action 模板」面板显示：**3 个模板**，全部状态为「活跃」。

---

### 第三步：Browse 页执行

**路径**：顶部导航 → **浏览** → 左侧选择 **Order** 类型

#### 3-0 观察自动状态推断

进入列表，直接观察：

- 每个 Order 对象右侧出现**彩色小圆点**：处理中黄色、已发货紫色、已送达绿色、已取消红色
- 系统自动从 `status` 字段值匹配状态机定义，**无需手动设置**
- 搜索框下方出现 5 个过滤标签：**全部 / 处理中 / 已发货 / 已送达 / 已取消**
- 点击 **「处理中」** → 列表只显示 or2、or7、or10 三条订单，右上角显示 `3 / 10`

#### 主流程：or2 走完完整履单链路

**阶段一：发货**

1. 保持过滤条在「处理中」，点击 **or2** 进入详情
2. 头部显示黄色徽章 `● 处理中`（从 `status: Processing` 自动推断）
3. 字段区显示：`total_amount: 8300`、`currency: USD`、`customer_id: cu1`、`priority: Medium`
4. **⚡ Actions** 面板显示「**1/3 可用**」，只有 **发货** 按钮
5. 点击 **「发货」** → 弹出对话框，填写：
   - `total_amount`：`8300`（已预填）
   - `tracking_no`：`SF1234567890`
   - `shipped_by`：`仓库李四`
6. 点击「执行」→ 状态变为紫色 `● 已发货`
7. Actions 面板切换为「**1/3 可用**」，只显示 **确认收货** 按钮

**阶段二：确认收货**

8. 点击 **「确认收货」** → 填写：
   - `received_by`：`客户张三`
   - `delivery_note`：（可留空）
9. 点击「执行」→ 状态变为绿色 `● 已送达`
10. Actions 面板显示「**0/3 可用**」——终止状态，无可用操作

**查看执行历史**

11. 向下滚动，点击「执行历史」→ 展开显示 2 条记录：
    - `✓ 发货        处理中 → 已发货`
    - `✓ 确认收货   已发货 → 已送达`

#### 分支流程：or7 取消订单

1. 返回列表，点击过滤条 **「处理中」**，点击 **or7**
2. 头部显示 `● 处理中`，字段显示：`total_amount: 280000`、`currency: JPY`、`priority: High`
3. Actions 面板显示「**1/3 可用**」，只有 **发货** 和 **取消订单** 两个按钮

> 等一下——or7 的起始状态 Processing 对应两个 Action（发货 + 取消订单），所以应该显示「**2/3 可用**」。

4. 点击 **「取消订单」** → 填写：
   - `reason`：`客户主动申请取消，货源紧张无法保证交期`
   - `cancelled_by`：（可留空）
5. 点击「执行」→ 状态变为红色 `● 已取消`
6. 返回列表，or7 不再出现在「处理中」过滤中，出现在「已取消」列表

> **向客户说明**：
> - `status` 字段值与状态机 `name` 自动匹配，列表即刻显示彩色状态点，无需手动维护
> - 每个阶段只显示当前合法的操作按钮，业务人员不会误操作
> - 状态过滤条 + 搜索框配合，10 条数据演示，实际支持数十万条
> - 执行历史实时写入数据库，刷新页面后依然保持

## 示例二：Invoice 发票收款流

> 系统中已有 8 条 Invoice 对象（inv1–inv8），字段包含 amount / currency / order_id / status，状态值 Pending / Paid。本示例在此基础上增加「逾期」状态，演示催款和收款的完整流程。
> 预计时长：15 分钟

---

### 第一步：配置状态机

**路径**：模型 → 点击 **Invoice**（AR）→ 展开「状态机」面板

#### 1-1 从数据导入已有状态

1. 点击 **「从数据导入」**
2. 下拉框选择 **`status`** 字段，检测到 2 个枚举值：`Pending`、`Paid`
3. 全部勾选，选择颜色，点击 **「导入 2 个状态」**

#### 1-2 手动补充「逾期」状态

点击 **「+ 新建状态」**，填写：

| 字段       | 值           |
|----------|-------------|
| 名称（英文） | `Overdue`   |
| 显示名称   | 逾期          |
| 颜色       | `#f97316`（橙色）|

最终状态列表：

| 名称（英文） | 显示名称 | 颜色       | 标记       |
|-----------|---------|-----------|-----------|
| `Pending`  | 待付款   | `#3b82f6` | ☑ 初始状态 |
| `Overdue`  | 逾期     | `#f97316` |           |
| `Paid`     | 已付款   | `#10b981` | ☑ 终止状态 |

#### 1-3 配置转换规则

| 起始状态 | 目标状态 | 说明              |
|--------|--------|-----------------|
| 待付款   | 已付款   | 客户正常付款        |
| 待付款   | 逾期    | 超过付款期限标记逾期  |
| 逾期    | 已付款   | 逾期后补款完成       |

观察状态图：出现**回路结构**，逾期后仍可完成付款。

---

**路径**：同一 Invoice 详情页 → 展开「Action 模板」面板 → 点击「+ 新建」

#### Action 1：标记已付款

| 字段          | 填写内容          |

| 名称（英文）   | `mark_paid`     |
| 显示名称      | 标记已付款         |

| 执行后状态    | 下拉选**已付款**   |

**参数配置**：

1. 点击「从字段选择」→ 勾选 `amount`（number）→ 添加
2. 点击「+ 手动添加」两次：
   - `paid_by`，string，☑ 必填（付款确认人）
   - `payment_ref`，string，☑ 必填（付款凭证号）

| 参数名          | 类型    | 必填 |
|--------------|--------|------|
| `amount`     | number | ☑    |
| `paid_by`    | string | ☑    |
| `payment_ref`| string | ☑    |

点击「创建」→「激活」。

#### Action 2：标记逾期

| 字段          | 填写内容          |
|-------------|-----------------|

| 显示名称      | 标记逾期           |

#### Action 3：发送催款提醒

**参数配置**：

### 第三步：Browse 页演示

**路径**：顶部导航 → **浏览** → 左侧选择 **Invoice** 类型

#### 3-0 观察自动状态推断

进入列表：

- inv2、inv4、inv7、inv8 右侧显示**蓝色点**（Pending → 待付款）
- inv1、inv3、inv5、inv6 右侧显示**绿色点**（Paid → 已付款）
- 状态过滤条：**全部 / 待付款 / 逾期 / 已付款**
- 点击「待付款」→ 显示 4 条待付款发票，右上角 `4 / 8`

#### 主流程：inv2 正常付款

1. 点击过滤条 **「待付款」**，点击 **inv2** 进入详情
2. 头部显示蓝色徽章 `● 待付款`
3. 字段区：`amount: 8300`、`currency: USD`、`order_id: or2`
4. **⚡ Actions** 面板显示「**2/3 可用**」：**标记已付款** 和 **发送催款提醒**
5. 点击 **「标记已付款」** → 填写：
   - `amount`：`8300`
   - `paid_by`：`财务王五`
   - `payment_ref`：`PAY-2024-0110`
6. 点击「执行」→ 状态变为绿色 `● 已付款`
7. Actions 面板显示「**0/3 可用**」（终止状态）
8. 展开执行历史 → `✓ 标记已付款   待付款 → 已付款`

#### 逾期催款流程：inv4

1. 返回列表，点击 **「待付款」**，点击 **inv4**
2. 头部显示 `● 待付款`，字段：`amount: 9800`、`currency: GBP`、`order_id: or4`

4. 点击 **「发送催款提醒」** → 填写：
   - `channel`：`邮件`
   - `reminder_note`：`请尽快完成付款，避免产生逾期费用`
5. 点击「执行」→ 状态不变，仍为 `● 待付款`（此 Action 无状态跃迁）
6. 执行历史记录一条：`✓ 发送催款提醒   待付款 → 待付款`
7. 点击 **「标记逾期」** → 填写：
   - `overdue_days`：`15`
   - `noted_by`：`财务王五`
8. 点击「执行」→ 状态变为橙色 `● 逾期`
9. Actions 面板切换为「**2/3 可用**」：**标记已付款** 和 **发送催款提醒**（逾期同样可催款）
10. 客户最终付款，点击 **「标记已付款」** → 填写付款信息 → 执行
11. 状态变为绿色 `● 已付款`
12. 展开执行历史 → 完整 3 条记录：
    - `✓ 发送催款提醒   待付款 → 待付款`
    - `✓ 标记逾期      待付款 → 逾期`
    - `✓ 标记已付款    逾期 → 已付款`

> **向客户说明**：
> - 系统自动从 `status` 字段值匹配状态机，Pending/Paid 即刻显示对应状态色点
> - 手动补充的「逾期」状态无缝融入，与从数据导入的状态在系统中完全一致
> - `send_reminder` 不改变状态，仍记录执行历史，满足操作审计要求
> - 逾期后仍可正常付款，状态机回路符合真实业务逻辑

## 常见问题 QA

**Q：ActionType 可以跨系统调用吗？**
A：可以。应用级 ActionType（Saga 层）设计用于跨 Fold/Project 编排，Phase 4 实现后支持调用外部服务和第三方系统。

**Q：权限控制在哪里？**
A：Persona 字段声明哪些角色可执行。执行引擎接入时，系统读取当前用户 Persona，过滤不可用的 Action 按钮。

**Q：状态机是强制的吗？**
A：不是。没有配置状态机时，ActionType 仍可创建，起始/结束状态留空即可；状态流转控制为可选增强功能。

**Q：Action 执行失败怎么办？**
A：当前阶段执行失败返回错误信息并中止，不更新状态。Phase 4 Saga 编排引擎接入后，支持多步骤事务和自动补偿回滚。

**Q：执行历史可以导出吗？**
A：数据存储在 `action_executions` 表，后续可对接报表系统或通过 API 导出。
