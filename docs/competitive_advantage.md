## 四、三大结构性优势（PPT 核心论点）

### 优势一：数据主权 — Palantir 做不到的

**Palantir 的问题**：
- AIP 的 AI 能力依赖云端 LLM 服务，数据必须上传
- 金融、政务、医疗、军工客户面临严格数据出境合规限制
- Palantir 本身是美国公司，数据主权存在天然政治风险

**我们的方案**：
```
全部组件本地部署：
  LLM 推理  → Ollama（本地）
  向量检索  → qdrant（本地）
  图数据库  → NebulaGraph（本地）
  查询引擎  → DataFusion（进程内）

数据从未离开客户内网，满足最严格合规要求
```

**客户价值**：金融、政务、医疗客户可以放心使用 AI 能力，无数据泄露风险。

---

### 优势二：AI 零训练接入 — 颠覆传统 AI 集成模式

**传统 AI 集成的痛点**（包括 Palantir AIP）：
```
Step 1：收集业务数据                → 耗时数月
Step 2：人工标注训练集              → 成本百万级
Step 3：Fine-tune 领域模型         → 需要 ML 工程师
Step 4：业务变化 → 重新标注 → 重训  → 永无止境
```

**我们的方案**：
```
Ontology Schema 本身就是"结构化的业务知识库"

EntityType = Order（字段：order_no, status, amount）
ActionType = confirm_order（起始状态：pending，参数：confirmed_by）
StateDef   = pending → confirmed → shipped → delivered
LinkType   = Order -[BELONGS_TO]-> Customer

→ Schema 注入 LLM Prompt = 实时更新的业务字典
→ 通用模型（DeepSeek / Qwen）立即理解业务语义
→ 业务新增概念，Schema 更新，AI 立即可用
→ 零标注，零训练，零 ML 工程师
```

**客户价值**：
- 今天建好 Ontology，今天就能用 AI 问答业务数据
- 业务扩张不需要额外 AI 投入，Schema 驱动自适应
- 总拥有成本（TCO）比传统 AI 集成降低 **90%+**

---

### 优势三：AI 治理与操作安全 — 企业级 AI 的必要条件

**Palantir 的问题**：
- Action 可以挂在任意 Object Type 上，AI Agent 操作面模糊
- 没有结构化约束，AI 可能操作不该操作的对象
- 审计追溯依赖日志，不是系统性设计

**我们的架构约束**：
```
约束 1：只有 AR（Aggregate Root）对象才有 Action 入口
         → AI Agent 的操作面 = AR 的 ActionType 集合，天然可枚举
         → 非 AR 对象不可被 AI 误操作

约束 2：ActionType 声明允许的起始状态
         → 系统在执行前自动校验状态合法性
         → AI 无法触发不合法的状态跃迁

约束 3：每次执行写入 action_executions 表
         → AI 的每一个操作都有完整审计记录
         → 可追溯，可回滚，满足合规审计要求
```

**客户价值**：
- AI 的操作边界清晰，业务负责人可以审查"AI 能做什么"
- 状态机约束天然防止 AI 误操作，不需要额外的 AI 安全层
- 完整审计链满足金融/政务的合规要求

## 六、面向不同客户的价值主张

### 金融/政务客户
> "Palantir 的能力，加上您的数据永不离境的承诺"

- 完全内网部署，满足等保/行业监管要求
- 国产 LLM（DeepSeek/Qwen），无境外数据依赖
- 操作审计链完整，满足合规检查

### 制造/供应链客户
> "让您的业务数据真正活起来，今天建模，今天用 AI"

- Ontology 将 ERP/WMS/OMS 数据统一语义化
- AI 立即理解订单/库存/供应商等业务概念，零训练
- 自然语言查询：直接问"哪些供应商最近交货延迟？"

### 中型企业客户
> "Palantir 级别的能力，1% 的成本"

- 无天价授权费，按需部署
- 业务人员自己配置 Ontology，不需要 Palantir 驻场工程师
- Schema 驱动的 AI，随业务成长自适应
